文章看点 · NOTES

过去几年，人与 AI 的关系是「你问一句、它答一句」；而这篇文章要讲清楚的是，一场更深的转向正在发生——AI 正在从生成回答，走向维护状态、操作软件、委派工作、代表一个人去行动。作者横向拆了 14 家代表性产品（Meta Muse、Google Gemini Spark、Claude Cowork、xAI Grok Bot、Microsoft Scout、Siri AI、OpenAI Dots、OpenClaw+Hermes、Poke、Manus Cue、Instinct、Perplexity Computer、Buzz、Genii），逐一给出架构框图与「技术身份」，再从中抽提出个人智能体的五层通用骨架——界面、记忆与上下文、推理与编排、行动、权限，并给出四个判断：智能体身份正在成为新原语、智能体计算机正在变成大宗商品、运行时正演进为操作系统、以及人类的角色从操作者变为委托人。它提醒我们，个人 AI 之争早已不是模型跑分之争，而是谁更懂你、谁拥有运行时、谁掌握身份与信任之争。

个人智能体之争，本质上是在回答一个问题：软件该如何代表一个人、并为一个人而行动。

但此刻最重要的转变在于：AI 正在从生成回答，走向维护状态、操作软件、委派工作、并代表一个人去行动。

这些正在崛起的产品，并没有用同一种方式解决同一个问题：有的在做私人秘书，有的在做 AI 同事，有的给智能体配一台自己的电脑，有的给它一个身份，有的把即时通讯作为界面，有的把智能体嵌进操作系统，有的把它做成持续存在的数字员工，还有的在搭建让人与智能体在同一工作空间里成为对等参与者的基础设施。有意思的不仅是产品，而是每家公司心中那个「将定义个人智能体层」的架构。

02

FOURTEEN ARCHITECTURES

十四种架构，十四种哲学

下面按每家试图掌控的核心原语逐一走读，每家给出一张架构骨架与一句「技术身份」。

AGENT 01Meta Muse · 多智能体的个人超级智能

Meta 把 Muse 描述为能了解用户、在后台工作、访问邮箱与日历、使用 Shell、派生成群子智能体、在长时间轨迹上运行的个人智能体，并针对零样本工具调用、长上下文、提示注入感知与多智能体协同做了专门训练。关键原语是子智能体派生：一个大任务被拆成机票、酒店、日历、餐厅、行程单等专门化工作流并行推进。

TECHNICAL IDENTITY

个人上下文 + 长程智能体 + 多智能体编排 + 后台执行

AGENT 02Google Gemini Spark · 生态原生智能体

Google 的切入靠一项别的资产：上下文本就存在于它的生态里。Spark 是 7×24 后台运行、直接集成 Workspace 的个人智能体，跑在专用 Google Cloud 虚拟机上，由 Gemini 加智能体框架驱动，支持 MCP 扩展与 Chrome 网页执行。它不需要庞大的第三方插件——Google 已经拥有那张上下文图谱，价值在于跨应用上下文。

TECHNICAL IDENTITY

云智能体运行时 + 第一方上下文图谱 + 浏览器智能体 + Workspace 集成

AGENT 03Anthropic Claude Cowork · 长时间运行的知识工作者

这一支把 AI 当作员工而非助手。工作单元不是消息，而是项目。例如「分析季度财务、找出最大差异、撰写管理层评述并产出董事会报告」，需要发现文件、检查数据、推理关系、计算、生成中间产物、校验、成文——这是一条有状态的执行链，而非一次次孤立的 LLM 调用。

TECHNICAL IDENTITY

长时间任务智能体 + 计算机/文件访问 + 知识工作执行

AGENT 04xAI Grok Bot · 拥有持久计算机的智能体

xAI 把 Bots 定义为「始终在线、各有自己电脑的 AI 队友」：登录应用、跨邮箱与工具操作、后台持续推进、需人工批准时才回来找你；具名 Bot 跨会话保留记忆、文件与浏览器会话。同一账户下多个 Bot 共享一台持久云电脑，等于一个共享的智能体工作空间。因为万维网是为人类而建、多数网站没有 MCP 或智能体 API，计算机操作成了通用兼容层：智能体 → 浏览器 → 现有网站。

TECHNICAL IDENTITY

持久智能体 + 云计算机 + 浏览器 + 终端 + 多 Bot 协同

AGENT 05Microsoft Scout · 以身份为中心的企业智能体

Scout（2026 年 9 月更名为 Autopilot）跨 Teams、Outlook、OneDrive、SharePoint 工作并在后台运行。Microsoft 的关键创新不只是智能体式执行，而是智能体身份——智能体成为独立于用户的存在，于是企业授权模型变成「人的身份 + 智能体身份 + 权限策略 + 审计轨迹」。值得注意的是，这套基础设施是基于 OpenClaw 开源技术 构建、再叠加微软的企业安全与治理控制而成。

TECHNICAL IDENTITY

持久智能体 + 企业身份 + Microsoft Graph/365 上下文 + 治理

AGENT 06Apple Siri AI · 设备原生智能体

Apple 从操作系统向上切入。Siri AI 与 Apple Intelligence 深度集成，具备个人上下文理解、屏幕感知、系统级应用操作，以及跨信息、邮件、照片检索的能力。它有意思的属性是环境上下文：智能体知道用户正在哪里操作。Apple 不是在再加一个 app，而是让操作系统本身更「智能体化」。

TECHNICAL IDENTITY

OS 原生智能体 + 设备上下文 + 个人上下文 + 系统操作

AGENT 07OpenAI Dots · 始终在线的目标智能体

Dots（DevDay 2026 发布）把个人智能体推向「始终在线」：可定制、主动追求多步目标、通过 ChatGPT / Slack / Teams 运行、对敏感操作执行用户自定义规则。关键抽象是目标归属——普通助手等下一条消息，而 Dot 能围绕一个目标持续运作。报道还称 OpenAI 将推出会计、法务、市场等专家型 Dot。

TECHNICAL IDENTITY

始终在线的目标智能体 + 持久上下文 + 自定义规则 + 主动执行

AGENT 08OpenClaw + Hermes · 自己拥有的智能体运行时

与上面多数系统最大的不同在于所有权：你不必从某家厂商租下整个智能体栈，而可以自己拥有运行时。Hermes 提供跨会话持久记忆、由智能体管理的技能系统，并把 MCP 作为一等集成机制（含本地 stdio 与远程 HTTP）。其架构支持持久记忆、过程性技能、子智能体派生、并行执行、定时任务、多配置档、消息网关、终端与浏览器自动化。

TECHNICAL IDENTITY

用户可控的智能体运行时 + 持久记忆 + 技能 + MCP + 多通道网关

AGENT 09Poke · 消息原生的个人智能体

Poke 走了相反的路：不要求学新界面，而是把智能体做成一个联系人。它栖息在 iMessage、WhatsApp、Telegram、RCS 里，连接邮箱、日历、提醒、搜索与工具，并支持 MCP。这本质上是把对话作为控制平面：不再是「打开 app→找功能→配置→执行」，而是「发消息→意图→执行」。它的 Poke Human 系统还造出混合模式——工具不可用时回落到人工。

TECHNICAL IDENTITY

消息界面 + 个人智能体 + MCP/API + 人工升级

AGENT 10Manus Cue · 有自己身份、电脑和钱包的智能体

Cue 把架构从「让智能体访问你的资源」推进到「给智能体它自己的资源」：每个 Cue 都能拥有邮箱、电话、钱包和计算机，并支持多智能体协作。概念上的转变很硬：过去是「AI 用我的身份」，现在是「智能体拥有一个身份」；过去「AI 用我的电脑」，现在「智能体有一台电脑」；过去「AI 帮我付款」，现在「智能体可以有钱包和消费边界」。

TECHNICAL IDENTITY

持久数字员工 + 智能体身份 + 专用计算机 + 通信 + 金融能力 + 多智能体协作

AGENT 11Instinct · 感知上下文的个人代表

它的核心理念不是「给我一个任务」，而是「理解我的生活，并在需要有事发生时主动行动」。它把智能体接入邮件、消息、屏幕、音频、位置、设备等信号，用手机和电脑完成任务。这本质上是一个事件驱动的智能体：观察→检测→解释→决定→行动/询问。近期报道也强调，授予这类系统深度访问会带来安全影响。

TECHNICAL IDENTITY

环境上下文 + 持久的个人模型 + 设备控制 + 主动行动

AGENT 12Perplexity Computer · 为你的工作而生的智能体框架

Perplexity 明确把 Computer 定位为智能体框架（agent harness）：一个能调研、编码、浏览、构建、监控、排期、写作编辑的通用数字工作者，可部署子智能体、跑后台任务、连接 Gmail/Slack/Notion/日历。在 Windows 上它是跨 15+ 模型的编排器，在 Mac 上能操作本地应用、文件、信息、邮件、日历与 Comet 浏览器，可在 Mac mini 常驻、用手机审批。关键原语是跨模型、跨环境的编排。

TECHNICAL IDENTITY

智能体框架 + 模型编排 + 浏览器自动化 + 本地计算机控制 + 后台执行

AGENT 13Buzz（Block / Jack Dorsey）· 智能体原生的工作空间

Buzz 主要不是个人助理，而是一个智能体原生的协作环境：开源、可自托管，人与智能体都是一等参与者，构建在 Nostr 协议之上。每条消息、反应、工作流步骤、评审批准、git 事件，都是一条密码学签名的 Nostr 事件，中继作为唯一事实来源。它给智能体各自的密码学身份（身份/密钥对），于是智能体成了拥有持久身份的行为主体。

TECHNICAL IDENTITY

智能体原生协作 + Nostr 身份 + 事件日志 + Git + MCP + 智能体工作流

AGENT 14Genii · 住在 iMessage 里的个人智能体

来自 Intelligent Internet 的 Genii 把「消息原生」推得更远：输入手机号，一个联系人出现，你直接通过消息与智能体沟通。它具备持久记忆、主动触发、自己的计算机、Gmail/日历集成、语音交互与审批闸门。开源内核在 E2B 沙箱里部署 OpenClaw，凭据加密后存放在本地后端。安全模型很明确：想发送→同意闸门→用户批准→执行→记录批准；真正执行工作的运行时并不直接持有用户的长期密钥——这是智能体安全的关键模式。

TECHNICAL IDENTITY

iMessage 原生个人智能体 + 持久记忆 + 主动触发 + 沙箱化计算机 + 审批门控的行动

03

FIVE LAYERS

个人智能体的五个层次

纵观十四套系统，一套相当一致的架构浮现出来。

第 1 层 · 界面

人如何跟智能体对话？可以是聊天、消息、iMessage、语音、桌面、移动、Teams、工作空间、CLI。Poke 与 Genii 把界面推向消息，Siri 把它搬进操作系统，Buzz 把智能体做成协作频道里的一名参与者。

第 2 层 · 记忆与上下文

...

会话记忆 → 用户记忆 → 任务状态

→ 项目状态 → 环境状态 → 历史行为

个人智能体需要理解的不只是当前这条提示词。Hermes 显式地把持久的用户/智能体记忆与过程性技能分开，Genii 同样强调能跨越单次对话存续的记忆——这与无状态的聊天机器人有本质区别。

第 3 层 · 推理与编排

智能体要决定：目标是什么、需要哪些步骤、由哪个智能体来做、调用哪个工具、发生了什么、下一步做什么。这正是智能体编排出现的地方。重要的原语正在从 工具调用（Tool Calling） 转向 智能体调用（Agent Calling）。

第 4 层 · 行动

有三种日益重要的行动机制：API 优先（快且确定，但依赖服务暴露合适接口）、MCP 优先（更标准化，让智能体发现文件系统、GitHub、数据库、浏览器等外部能力）、以及计算机操作（更慢更不确定，却能让智能体与「最初为人类而造的软件」交互）。于是计算机成了一通用集成层。

第 5 层 · 权限

最被低估的部分是权限。模型也许有能力执行某动作，但不意味着它应被允许。安全的架构会把「推理」与「授权」分开：模型决定「我该发这封邮件」，策略引擎决定「你有权限发吗」。这就是为什么企业与个人智能体越来越需要限定范围的凭据、审批闸门、隔离沙箱、审计轨迹、消费限额、回滚与终止开关。


04

EMERGING PATTERNS

几个正在成形的判断

把版图谱摊开，四条趋势线反复出现。

智能体身份，正成为一种新原语

Cue 和 Buzz 让一个想法格外清晰：智能体本身也许需要一个身份。不再只是「人类 → 应用」，而是「人类 → 个人智能体 → 智能体身份 → 工具/服务」，身份之下挂着邮箱、电话、计算机、钱包、凭据、记忆与声誉。这可能成为智能体经济的基础原语之一。

智能体计算机，正在变成大宗商品

计算机正在成为运行时的一部分：CPU、内存、文件系统、浏览器、终端、会话状态、凭据、网络、桌面——几乎就是一台普通电脑，只不过主用户是 AI。其后果相当重大：

未来的智能体运行时，看起来可能更像一台云工作站，而不是一个 API 端点。

从运行时到智能体操作系统，再到智能体团队

架构最终会长成「身份 / 记忆 / 技能 → 运行时 → MCP·浏览器·计算机 → 应用 → 现实世界」的样子，OpenClaw/Hermes 因此更像智能体运行时平台而非助手。同时，一个个人智能体会成为编排器，派出调研、编码、财务、内容、排期等子智能体：人 → 智能体管理者 → 智能体团队。

下一步，是智能体之间的通信与「智能体即商业」

一旦存在多个智能体，问题就变成「它们如何沟通」。想象一次交易：你的个人智能体 → 旅行智能体 → 航司智能体 → 酒店智能体。人不必亲自对接每个服务，由智能体之间协商，从而催生一种由智能体撮合的经济。互联网也随之从「人类操作的网站」，转向「智能体之间协商的服务」。

06

OWNERSHIP & DELEGATION

谁拥有智能体？人类会怎样？

这一点最终会切割整个市场。

1

厂商拥有的智能体：公司 → 模型 → 运行时 → 记忆 → 智能体，许多云原生助理属于此类。

2

用户拥有的智能体：用户 → 运行时 → 模型 → 记忆 → 工具 → 智能体，OpenClaw 与 Hermes 更接近这一理念。

3

智能体拥有的身份：智能体自带身份、计算机与资源，Cue 把方向推向这里。

4

智能体原生工作空间：人类 ↔ 智能体 ↔ 智能体 ↔ 人类共享一个空间，Buzz 是重要范例。

这些不只是产品选择，它们意味着「谁掌控数字劳动力」的不同未来。而人类的角色也在变：今天是操作者（operator），明天是监督者（supervisor），最终是委托人（principal）——人类设定目标、偏好、边界、权限与审批规则，智能体负责调研、协调、执行、监控与迭代。

智能体世界里最有价值的技能，也许不是提示词工程，而是「委派工程」。

你需要判断：什么该委派、什么该保留人类控制、智能体该接收什么上下文、该拥有哪些凭据、哪些行动需要审批、它能自主运行多久、我如何审计它、又如何叫停它。这更接近于管理一支数字劳动力，而不是使用传统软件。

个人智能体时代

这一演化可以总结为一条链：搜索引擎（找信息）→ 聊天机器人（理解信息）→ 副驾驶（协助工作）→ 智能体（执行任务）→ 个人智能体（管理目标）→ 数字工作者（持续运作）→ 数字代表（代你行事）→ 智能体网络（与其它智能体协商协作）。

这些产品不只是「AI 助手市场」里的竞争者，而是一个更大架构不同组成部分的实验。真正的问题在层层升级：

聊天机器人时代问「AI 能告诉我什么」，智能体时代问「AI 能为我做什么」，个人智能体时代问「我能安全地把我委派给一个代表我的软件实体吗」。

而下一阶段也许会问一个更大的问题：当我的智能体能够雇佣、谈判、并与其它智能体协作时，会发生什么？正是在这里，个人 AI 不再像又一个软件功能——它开始像一个全新的计算层。
