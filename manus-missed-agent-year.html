Manus率先定义了通用Agent的产品想象，却错过了从点火者变成规则制定者的窗口。

2026年9月1日，Manus宣布恢复独立运营。

创始团队重新掌舵，云电脑、计划任务2.0、小企业版等产品密集上线，一个被称为公司历史上“最雄心勃勃”的Work产品也在路上。合伙人张涛说，团队士气高涨，Manus从未停止构建。

这当然是一则关于“回来”的消息。但如果把时间拨回2025年3月，问题就会变得尖锐：那个曾经最接近“AI替你干活”的产品，为什么需要重新证明自己的相对领先？

过去一年半，Manus经历了融资、迁往新加坡、被Meta收购、交易遭中国监管叫停，再到腾讯等原股东被报道参与回购，最终正式恢复独立。鞭牛士梳理的这条时间线像一部情节过密的商业剧。可就在Manus忙于改变归属的同时，AI Agent完成了一次更安静、也更残酷的爆发：它不再主要以一个独立产品的形态出现，而是进入了浏览器、代码编辑器、Office、GitHub、搜索框和操作系统。

这里所说的“失速”，不是指Manus已经出现收入、用户量或市场份额下滑——公开资料不足以支持这种结论。它指的是先发优势的快速折旧：Manus率先定义了通用Agent的产品想象，却没有在行业全面跟进之前，把这份想象沉淀为自己掌控的模型、入口和工作流标准。

Manus错过的不是一年的发布时间，而是一段定义产业的窗口。

01

FIRST MOVER

第一个把未来演给所有人看的人

Manus在2025年3月走红，不是因为它发明了Agent，也不是因为它拥有当时最强的基础模型。它真正击中市场的，是把一个长期停留在论文、框架和开发者社区里的概念，拍成了普通人一眼就能看懂的产品演示。

你提出目标，它拆解步骤；你关掉页面，它继续在云端工作；它会浏览网页、操作软件、写代码、整理资料，最后不只交付一段回答，而是交付一个结果。

这套叙事完成了一个关键转换：ChatGPT时代的AI是在对话框里“告诉你怎么做”，Manus则试图跨出对话框“替你做完”。它让“Agent”第一次摆脱技术名词的抽象感，变成一种可以被想象、被转发、被排队争抢邀请码的消费产品。

先发优势由此建立，但它建立在一个危险的位置上。

Manus最容易被看见的部分——任务规划、网页操作、代码执行、云端沙箱——也恰恰是最容易被基础模型公司、开发平台和开源生态迅速吸收的部分。它向市场证明了需求，却没有因此独占供给。就像第一家把触屏手机做得惊艳的公司，并不会自动拥有触屏本身。

就在Manus发布后几天，OpenAI于2025年3月11日推出Responses API、Agents SDK，以及内置的网页搜索、文件检索和Computer Use工具。开发者不必再从头拼接一个Agent的眼睛、手脚和调度系统，平台开始把这些能力做成标准件。此前已进入研究预览的Claude Code，也在5月随Claude 4正式开放；同月，Google在I/O上展示Project Mariner、Jules和Gemini Agent Mode，微软则把Agent送进GitHub、Office、Windows与Copilot Studio；7月，阿里发布Qwen3-Coder与Qwen Code。Agent不再只是一种产品创意，而是全行业共同建设的能力层。

这是Manus的第一重困境：它最先集中展示的能力，后来迅速变成行业公共能力。


02

COMMODITIZATION

当“像Manus”变得越来越便宜

AI产品的先发优势有一种反常识的衰减方式。

传统软件可以依靠功能数量、数据积累和用户迁移成本形成壁垒。Agent却高度依赖它下面的模型。模型推理更强一次，任务规划就可能更稳；上下文更长一次，跨文件和跨页面协作就可能少丢一次信息；工具调用更可靠一次，原本需要产品团队精心编排的流程就可能被模型直接完成。

因此，Agent创业公司的产品进步，常常会被模型公司的能力升级“平移”给整个市场。

协议又进一步加速了这种扩散。Anthropic推出MCP，让模型连接外部工具和数据的方式趋于标准化；Google推动A2A，让不同Agent之间可以通信协作；OpenAI的Agents SDK则把多Agent交接、护栏和可观测性装进开发工具箱。过去需要一家创业公司自己打磨的编排能力，逐渐变成开发者可以调用的公共部件。

这并不意味着Manus没有技术。问题在于，用户很难感知一家公司在底层编排上领先10分，尤其当拥有更强模型、更低调用成本和更大入口的平台公司，可以用一个版本更新迅速缩小差距。

Agent时代的产品竞争因此出现了一种“演示与生产的不对称”。演示只需在一个精心选择的任务上成功一次，生产则要求它在无数模糊、脏乱、带权限和异常状态的任务中反复成功。前者制造惊叹，后者消耗算力、工程、人力与耐心。

「演示只需成功一次，生产则要求在混乱的真实世界里反复成功。」

真正投入使用后，用户关心的也不再是Agent会不会移动鼠标，而是它做错后谁来负责，付款前是否确认，登录态是否安全，失败能否恢复，过程能否审计，费用是否比人工更划算。一个通用Agent“什么都能做”的承诺，会迅速变成“每一种失败都要处理”的工程负担。

这也是为什么，代码Agent成为过去一年较早显现可验证价值的典型场景之一。

代码有天然的验收机制：能不能编译，测试是否通过，CI是否报错，补丁能不能被审阅。Claude Code、Codex、GitHub Copilot coding agent、Jules和Qwen Code进入的不是一片空白，而是一条已经存在的工作链。它们知道从哪里取任务，在哪里修改，怎样验证，又向谁交付。

相比之下，让通用Agent“帮我规划一次旅行”听起来更自由，却很难定义唯一正确的结果。航班价格会变，酒店偏好不清晰，支付需要授权，任何一步出错都可能让此前的推理失去意义。通用不是更宽的护城河，有时只是更宽的责任边界。


03

DISTRIBUTION

爆发的Agent，正在从产品里消失

如果只统计过去一年出现了多少个“通用Agent”，很容易得出赛道降温的结论。真正的变化恰好相反：Agent正在爆发，只是越来越少以“请打开一个全新的Agent网站”这种方式爆发。

OpenAI把Operator的浏览器操作和Deep Research的研究能力整合进ChatGPT Agent，依靠ChatGPT已有用户完成分发。Google让Mariner连接浏览器，让Jules连接GitHub，让Gemini Agent Mode连接自家应用。微软把Agent放进企业已经购买的Microsoft 365、Windows、GitHub和身份权限体系。Perplexity用Comet争夺浏览器入口。国内厂商也在把Agent能力嵌入搜索、办公、编程、电商和超级应用。

Agent真正适合存在的地方，往往不是一个孤立的应用，而是任务本来发生的地方。

它需要读取你的文件，继承你的权限，理解团队上下文，调用已经付费的软件，并在原工作流里交付结果。入口在这里不是流量按钮，而是完成任务所需的账户、数据、信任与反馈系统。

这让独立通用Agent处在一个尴尬位置：能力向下受制于模型，分发向上受制于平台，中间又要承担最昂贵、最复杂的执行层。

能力向下受制于模型，分发向上受制于平台。

Manus在爆红时拥有品牌，也曾拥有稀缺感，但品牌和邀请码不足以抵抗入口的重力。当“替你完成任务”成为ChatGPT里的一个模式、Chrome里的一个按钮、GitHub里的一名协作者，用户为什么还要专门打开另一个网站，把文件、账户和信任重新交一遍？

独立Agent并非没有机会。它必须拥有平台拿不走的东西：对某类工作流更深的理解，一套持续积累的任务数据，一个结果可验证的垂直闭环，或者真正跨平台而不偏向任何生态的执行能力。否则，所谓“通用”很容易沦为模型能力的展示橱窗，而不是一家公司的长期资产。


04

OWNERSHIP

被交易占用的产品时间

如果说技术平台化是所有Agent创业公司共同面对的压力，那么Manus过去一年半的特殊变量，是资本与监管事件反复改变了公司的组织环境。

2025年4月，Manus完成Benchmark领投的7500万美元融资，估值约5亿美元。此后公司将总部迁往新加坡，并调整中国团队。2025年12月29日，Meta以约20亿美元完成收购；2026年4月27日，中国国家发改委要求撤销该交易。到8月，财新援引接近Manus的人士称，腾讯、真格基金、红杉中国等原主要股东以约20亿美元从Meta回购股份；9月1日，Manus正式宣布恢复独立运营。回购参与方和价格来自媒体信源，并非公开交易文件披露。

这条路径看上去证明了Manus的稀缺：从5亿美元融资估值到约20亿美元交易价格，先被全球平台买下，又被原股东买回。但从产品竞争的角度看，它也留下了一段难以忽略的组织折返。

一次并购从来不只是股权文件发生变化。团队通常需要回答产品怎样接入母公司，技术栈如何整合，数据放在哪里，用户条款如何调整，人员向谁汇报；交易撤销后，同样的问题又要反向处理。Manus宣布因与Meta分拆及部分地区监管要求，删除部分2025年12月29日及以后产生的用户数据，可以被视为这段折返留在产品层的一个外部迹象。

公开信息无法说明这段过程究竟消耗了多少研发时间，也不能据此把产品差距全部归因于并购。更谨慎的说法是：所有权连续变化大概率扰动了产品优先级与组织注意力，但影响程度无从量化。与此同时，竞争对手围绕模型、协议、入口和企业工作流保持了连续迭代。

这构成Manus的第二重困境。Agent产品需要的不是偶尔发布一个亮眼功能，而是长期修复失败案例、积累任务轨迹、建立用户授权习惯、降低单位任务成本。模型会变，网页会变，接口会变，监管也会变。稳定本身就是产品能力。

这让“Manus从未停止构建”这句话听起来既真实，又带着防御意味。团队确实上线了Branch、Auto-Publish、智能PPT、Plan Mode、云电脑与计划任务等功能。但行业的评价标准已经从“还在不在更新”，变成“是否已经占住一条不可替代的工作链”。

功能发布速度可以追回，组织学习的连续性更难追回。


∞

EPILOGUE

回来之后，Manus面对的是另一场比赛

恢复独立不是故事的结尾，而是Manus第二次创业的起点。只是这一次，它不能再仅靠把未来演示出来获胜。

2025年3月，市场需要一个产品证明Agent可以从回答走向行动。Manus完成了这个任务。到2026年，证明题已经变了：Agent能否稳定进入真实工作，持续创造可衡量的价值？Anthropic发布的《2026年AI Agent现状报告》称，在其调查的500多名技术领导者中，80%的受访组织报告了可衡量的投资回报。作为厂商发布的调查，这个数字受样本构成与统计口径限制，不能代表全部市场；但它至少提供了一个信号：企业采用者正在把注意力从功能演示移向回报测量和规模化部署。

Manus即将推出的Work因此值得关注。这个名字本身像是一种迟到但正确的转向：从无边界的任务展示，进入有上下文、有权限、有验收标准的工作场景。

但“Work”不能只是再多几个办公功能。它必须回答三个更深的问题。

它能否拥有独立于模型升级的任务记忆与工作流资产？能否在跨应用执行中，比平台自带Agent更中立、更完整？能否把一次性的惊艳交付，变成用户每天愿意授权、愿意付费、失败后仍愿意再试的稳定关系？

这三件事不会像生成一份PPT那样容易被演示，却决定了Manus究竟是一家Agent公司，还是一段被行业吸收的产品灵感。

Manus没有错过AI Agent。它是这一轮浪潮最早的点火者之一。它错过的是从点火者变成规则制定者的窗口：品牌势能最强时，尚未来得及把势能沉淀为入口；最接近全球平台时，又因跨境监管被迫折返；重新独立时，通用Agent已经从一类产品变成主要平台普遍争夺的下一层界面。

Agent的爆发，不是屏幕上又多了多少个会自动点击的机器人，而是软件开始重新分配“谁来理解意图、谁来调用工具、谁来承担结果”。竞争的单位从模型回答变成任务闭环，护城河从演示能力转向工作入口，产品速度也不再只由研发决定，还由资本结构、数据边界和组织稳定性共同决定。

2025年的Manus让所有人看见了一只会行动的手。2026年的问题是：这只手究竟握住了什么。

如果握住的仍只是一个网页里的通用能力，它很可能继续被更强的模型和更大的平台追平；如果它能握住一条真实、长期、可验证的工作链，那么被错过的一年未必意味着终局。

只是下一次，市场不会再为“它能做什么”排队。市场要看的是，它究竟替谁，把什么事情，日复一日地做成。
