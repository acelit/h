§01 · THE SHIFT产品老A

范式在换：
从循环到图

这不是给循环换皮，而是控制权的一次搬家。

过去两年，做 AI Agent 的默认写法是——把模型丢进一个 while 循环里，让它自己看状态、自己选工具、自己判断"是不是完成了"。这套东西叫 Loop Engineering，也是 ChatGPT tool-use、ReAct、AutoGPT、Claude Code、Cursor Agent 的共同骨架。

但从 2026 年初开始，一个更工程化的说法在框架侧站稳脚跟：Graph Engineering——把 Agent 写成一张显式的计算图：节点是模型调用、工具、检索；边是控制流和数据流。工程师负责画图，模型负责填空。

"Loop 是把方向盘交给模型；Graph 是把地图交给模型，方向盘还在工程师手里。" — 编者按
§02 · DEFINITION产品老A

什么是
Graph Engineering

把 Agent 的控制流从模型手里拿出来，交回给工程师，用一张有向图显式表达。

图上每个节点是一个职责明确的原子——"起草回复"、"调检索"、"跑一段 Python"、"叫审核"；边是"跑完之后去哪"，可以是硬编码顺序、条件分支、并行 fan-out、循环回退。整张图共享一个可 checkpoint 的 State 对象，节点读写它、图引擎推进它。最早由 LangGraph、Pocketflow、Burr、Google ADK 等框架抽象成型。

①拆节点

把塞进一个大 prompt 的活儿，拆成职责单一、可单测的节点；每个节点自己就是可离线跑的函数。

②画边

确定的顺序写硬边；模棱两可的分支交给"路由节点"——模型不决定"下一步做什么"，只从已列好的路里挑一条。

③管状态

显式 State schema，谁读谁写明明白白；每一步可 checkpoint，出错能从任意节点续跑。

④插人类

Human-in-the-loop 成为一等公民——图可以在任意节点暂停等审批，而不是"把循环打断"这种脏活。

§03 · DIAGRAM A产品老A

Loop：模型在
闭环里自我决策

它的力量在于极致的灵活——任何没见过的任务形状都能"想办法"，不需要提前建图。Claude Code、Cursor、Devin 都是这个骨架的极致优化版。

但痛也熟悉：长任务会漂、失败不可复现、回归测试无法建立、产线稳定性靠 prompt 手艺撑着。这些不是 bug，是"让模型自由"的另一面——工程性让位。

§03 · DIAGRAM B产品老A

Graph：工程师画图，
模型只填空

确定的顺序是硬边；模棱两可处放一个 Route 节点，让模型从预设路径里挑一条。任何节点都能暂停等人工审批（Human），每一步的 State 都可 checkpoint、可回放。

真正让它成为"名字"的，是 2026 上半年一系列生产事故的反思——纯循环 Agent 在长任务里，失败模式几乎不可复现，也几乎不可回归测试。

§04 · HEAD-TO-HEAD产品老A

十项对比：Loop vs Graph

只对比工程属性，不评价谁更"聪明"——同一个模型，两种骨架，工程体验截然不同。

维度ALoopBGraph
控制流模型每步自己决定下一步做什么。工程师画好节点与边，模型只做局部决策或从预设路径挑一条。
状态管理状态藏在上下文窗口里，随对话滚动。显式 State schema，可读可写、可 checkpoint、可回滚。
可预测性低——同输入两次可能走两条路。高——图形状固定，路径可枚举、可回放。
可调试性看整段 trace，靠人眼找漂移点。逐节点看输入输出，State diff 一目了然。
并行能力顺序执行为主，靠模型想到"能并行"很难。fan-out 是图原语，独立子图天然并发。
版本化版本 = prompt 文本 + 工具集。版本 = 图拓扑 + 节点 prompt + State schema。
Human-in-loop需要"打断循环"这种脏 hack。一等公民——任何节点都能暂停等审批。
回归测试难——路径无法枚举。节点级单测 + 完整图端到端 replay。
失败模式漂移、死循环、无限重试、忘记目标。节点级失败，边界清晰，重试语义明确。
擅长场景探索性任务、编码副驾、开放问答。已知形状的生产工作流、审批链、合规场景。
§05 · WHY NOW产品老A

为什么是
现在火起来

四股推力在 2026 上半年同时到位——缺一股，它都还只是框架文档里的一页。

01 · OPS

产线在还债

2024–2025 一轮 Agent 上线潮后，2026 是"回头修 bug"的一年——SRE 拿着日志问"为什么这个 case 走了这条路"，Loop 给不出答案，Graph 至少能给出 State diff。

02 · COST

模型不再稀缺

推理成本从"每次调用心疼一下"降到"随便打"，一个节点里塞两次 LLM 校验也不心疼；细粒度节点才成为可能——之前的 Loop 是被成本逼出来的粗粒度。

03 · REG

合规接入

金融 / 医疗 / 政府场景要求"每一步为什么这么做"可追溯；Loop 的"模型自己决定"进不去这些门，Graph 的显式路径是准入的必要条件。

04 · TOOL

框架就位

LangGraph、Google ADK、Semantic Kernel Process、Pocketflow、Burr 在 2025 下半年至 2026 初集中成熟——画图的成本从"自己造轮子"降到"import 一下"。

§06 · DECISION产品老A

什么时候
用哪个

判据只有一条：任务形状是否已知。要自主性选 Loop，要可预测与可审计选 Graph。

选 Loop

WHEN · 任务形状每次都不一样
  • 写代码副驾 / 开放问答
  • 研究型探索、一次性脚本
  • 还在做 discovery 的 MVP
  • Claude Code / Cursor 这类工具选 Loop 是对的——用户明天想要什么谁都不知道

你要的是模型的自主性；硬建图只会把不确定性提前锁死在错的地方。

选 Graph

WHEN · 形状已知，要跑一万次
  • 客服工单分诊、合同审查流水线
  • 财报解读、发票核销
  • 多方审批、有回滚需求的操作型 Agent
  • 合规敏感、需要全程可追溯的场景

你要的是可预测与可审计；牺牲一点随机应变是划算的。

更实际的做法是组合：外层 Graph 定骨架，节点内塞一个小 Loop 允许自由发挥——既有边界又有余地。2026 下半年的主流架构会长这个样子。 — 组合策略
CLOSING · 一句话带走产品老A

不是 Loop 输了，
是 Loop 该退回它擅长的地方——探索；
而生产线上，Graph 是把
"能跑"变成"能维护"的关键动作。

同一个模型，两种骨架。控制权从模型手里回到工程师手里，不是不信任智能，而是让智能在边界内可靠地发生。
