01

BOTTLENECK

模型都快到 AGI 了，那还难在哪

高策说自己对 AI 的态度在今年 2 月转了一次弯。他之前做底层，代码复杂、对智能要求高，一直不太信 AI 能写好。直到那个月，他手写的领域被模型干净利落地接了过去，“甚至我现在感觉模型已经到了 AGI 的水平 了”。他接下来信的是成本会照 scaling law 往下走， 一年降十倍没问题 。

智能不缺，那缺什么。高策的判断是，大家在这个方向上都发现了执行里能带来 aha 的地方，可 眼下能办成的事还远远不够 。他甚至对模型能不能把聪明迁移过来存疑。

他说他们自己的交互 bench 上，跑分最高的往往不是当下最好的那几个模型。工作场景之所以看着被验证了，是因为它能写代码、能做 PPT，“这其实还是 coding 本身”，一旦落到交互、落到 personal agent，“ 模型的泛化性没有想象中那么强 ”。Muse 那边也是同样的看法，所以要自己去训模型，把 browser use 和交互表达这块补上。


02

MEMORY

同样一封邮件，它读不出你看邮件的逻辑

聊到差异化，高策把它拆成两层，一层是 memory 记忆 ，一层是 proactive 主动 。他强调，记忆这一层真正的功夫在于 把上下文用出价值 ，光收得多不算本事。

训练的时候大家都讲 GPU 利用率，他说在 harness 这一层， context 利用率同样重要 。光把上下文丢给模型、指望它泛化，通常不如人做得好。“我用邮件用了很多年，我其实是某种意义上的邮件小专家”，他看邮件的逻辑和模型训练出来的逻辑很不一样，人类的 rubrics 在这里是有价值的。

他把这条讲成了一个具体观察。给你一份邮件，普遍的扫法是翻一遍收件箱、发件箱，猜你是什么人。可发出去的邮件往往比收件箱信息密度更高，因为你写出去的时候带着意图，会把自己交代清楚，比如要跟谁合作，先自我介绍一段，那一段里的信息远超过收件箱。

收件箱是别人对你的意图，发件箱是你对别人的意图

Town 能把邮件处理得格外好，也是这个道理。一封邮件进来，要不要处理、怎么处理、草稿怎么写，它能在底下铺出五层 subagent 去跑。 同样的上下文，谁嚼得更深，谁才有壁垒 。


03

PROACTIVE

主动比推荐系统还难，因为停留时长不能当目标

潘乱提了一句他一直在琢磨的矛盾：没有记忆的主动很容易变成骚扰，邮箱、短信、推送全都成了这个结果；只有记忆没有主动，它又只是一本档案，跟一年前那堆邮件没差别。怎么把这两样接起来。

高策说难就难在 主动是个开放问题 。工作场景是封闭的，做个 PPT、做个调研，指向明确，好不好一眼能评。主动不一样，它吃的是每天进来的增量信息，本身充满不确定，目标又特别主观，跟推送的频率有关、跟质量有关，甚至跟你当天的心情有关。产品前期你也没法像 A/B 实验那样去证明它推得对还是不对。

他还说 proactive 有点像 agent driven 的推荐系统，但比推荐系统复杂太多。推荐系统优化停留时长就够了，proactive 带着执行的属性，而且“ 在你这个应用里面，停留时长一定不是优化目标 ”。他不希望你在助理里待得越久越好，它是要替你解决问题的。真正难的是找一个肯为这产品负责的人，把他脑子里对信息架构的认知灌进系统设计里，这是工程和产品要一起 co-design 的事。

Suki 补了一个比喻。她说主动像两种下属，一种纯执行，你交代一堆上下文、推一下动一下，现在很多产品号称的主动背后其实是个定时任务。另一种是他真的懂你要什么， 自己排优先级 ，反过来告诉你“你有这个目标的话我能帮你做什么”。她觉得做好主动有四件事，理解用户本身、从用户反馈里学习、把频次控制住、再就是时效性，去年在意的事放到今天可能一点都不重要。

至于最省事的主动，高策说，“OPPO 什么大家都在不断给你发 push，谁不会啊”，做好它非常难。


04

PERSONA

怎么认识一个一直在变的人

人会换工作、结婚、生孩子， 过去的偏好会过期 。高策说这块大家都还在摸索，先看看别人怎么做。Instinct 的记忆系统前阵子在推特上被人逆向了，热过一篇文章，它里面专门有个 timeline，记你每天、每周发生了什么；Town 用类似 consolidation 的方式每天总结一下，也保留 recent updates。

他更看重“时间”这个维度，因为人的变化来自 delta，一部分来自聊天记录，一部分来自连进来的应用，未来还会来自物理世界。Today 现在有录音功能，录下来的往往就是你最近的状态。这里有个像时序处理的地方， 发生的时间和被记下来的时间都重要 ，他举了个例子，九月在飞书上写下“我今年 2 月公司没了”，事情在 2 月发生、9 月被记录，两个时刻都得留。人和人的关系又天生是一张图，跟 timeline 那种时序数据不是一种结构，怎么把这些融合进记忆再让 agent 召回，他说这是个很难、还在很早期的问题。

难还难在， 行为不等于偏好 。他现在邮箱里积了四千多封未读邮件，不做任何设计的话，系统会梳理出一大堆它以为你在意的主题，可那些你多半早就不关注了。为什么不读，要么是太多顾不过来，要么它本来就不重要。他反问了一句：“我未读邮件，你心里没数吗。”

健康是 Today 第一个去优化的场景，这里冒出一个具体的坑，叫 身份识别 。潘乱替普通用户发问：我跟它说小孩发烧了怎么办、父母血压高了怎么办、我太胖了怎么办，我都没说是谁，它怎么分清这件事属于我、孩子还是父母。高策说这也是很多 bad case 的来源，现在大家的做法都还原始，靠记忆召回去碰，没做专门处理，理想情况下它得先在记忆里找到生病的那个 entity 是谁、对应的过往是什么。


05

LESS NOISE

好的个人助理，得先学会少说废话

模型都爱多说。高策说这是有道理的，任务 token 越多、他思考得越久，大概率完成率越高。可 个人助理这个场景正好相反 。他说，“你说话多，是提高了我的认知负担，你做完事给我一个结果，这个体验是最好的。”

他把这件事追到了训练目标上，拿小米开放的 RL 过程举例，数据配比里六到七成是 coding， chat 只占百分之三点五 。想让交互有废话少的体验，得有一个真把体验当回事的模型来做，海外有几家在探，但最终还得回到模型这一层。

该开口之外的另一半，是能不能干脆把活干完，别来烦我。潘乱追问，AI 整理完这场会又生成八项待办，能不能顺手替我做了。高策说那一定是方向，等 token 便宜到一定程度，做错了我 declined 也没多少成本，前提是这个执行没有副作用。他说再往前一步，理想状态是执行的时候都不需要我 approve，因为 要我确认本身也是一种打扰 ，就像 Codex 的 automatic mode，会学你历史上都批过什么命令。

眼下绝大多数 personal agent 还停在信息获取这一层。他说用它问问最近有什么演唱会、哪些有票，它能做到，可那不是我真正关心的，“我对这个演唱会感兴趣，你直接给我买张票吧”。什么时候你可以自己办、什么时候必须我点头，这条线画清楚， 提醒、准备、确认、执行这个闭环跑通 ，才是 personal agent 往下一阶段走的标志。

「personal AI 的对立面不是工作，是高委托成本。」

这一代不用你先喂一大堆上下文，因为它已经进了你的生活、连了所有应用、认识你所有同事。高策给了个最不起眼的例子，他让 Today 帮忙约会，下午几点、约谁，它把日历全 book 好、邮件发出去，他一步不用做。过去他绝不会让 Codex 帮他约会。他的总结是，“是它的这一套记忆和主动性的设计机制，让它的委托成本， 低于我完成这些小事的总成本 ”，很多事才真的敢交出去。


06

MARKET

大厂还没认真下场，但它擅长的是另一件事

市场眼下还很小，也还没有 PMF。高策说大厂最擅长的，其实是“ 高举高打，拿资源去烧 ”，看见一个东西并且死磕它反倒不是它的长项，他听说千问和豆包年中看过这个方向，试了一阵很快放弃。创业公司要在这种竞争里活下来，靠的恰恰是 看见和坚持 。

这几家里他觉得真正有优势的是 Muse，主要它有钱。Muse 的架构是 agent in the sandbox，你不用它，那台虚拟电脑也在 24 小时跑着，成本压得很高，好处是服务单个用户的进程独立、不用背多租户复杂度，迭代反而快。Meta 愿意在这种不确定的方向上下注，罕见的是这次 Muse 发出来口碑很好。

但他给创业公司指的路子是学 Town，卖订阅，从一个 connector 里那个具体的场景，就是 email，把它做深做透，付费意愿就起来了，像个工具类产品那样一步一步 scale。他自己的判断是， 这个领域短时间内被高估了，长时间又会被低估 ，现在 Instinct 那点体量撑到百亿美金估值是很 hype 的阶段，长期会回到理性。

THE END

它想被记成的那句话

节目快结束，潘乱问他们希望用户用久了以后怎么描述 Today。Suki 说团队想过的 slogan 是 today is your day，她希望 Today 别再给人添一份 AI 焦虑，做一个 主动认识你、理解你的朋友 。

高策说的是另一层意思。他希望将来被记住的是，世界上有这么一款 AI 产品，是 为了降低它对你注意力的干扰而存在 的，不是为了多推内容和消息而存在。用户提起它的时候说的是，这东西让我有更多时间去生活、去散步、去踢球，而不是工作效率又高了、能接更多活了。
